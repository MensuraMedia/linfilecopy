LinFileCopy mockups

Ten screens that show how the GTK 3 app will look and behave before any UI code is written. The app works with local storage only: internal disks, removable drives and local storage arrays, with rsync as its only copy engine. Every icon on this page is a Phosphor SVG read from the local asset folder and inlined here, using the same icon IDs the app will ship with. Fonts are the system's own (Cantarell on GNOME); nothing is fetched from the network.

The windows follow your light or dark theme, the same way the app follows the desktop setting. Tags under each heading show which features the screen covers: B1–B10 are the basic features and #1–#20 are the advanced ones.

Validation explains why some options are unavailable for this job instead of hiding them.

4 · Preview results, delete confirmation and two-way conflicts

Preview runs the job as a dry run and lists every planned change. Running a mirror job that will delete files always asks first and gives the exact count, even when the user skipped the preview. A two-way preview shows the direction of each change and resolves conflicts according to the chosen policy.

7 · Scheduler

All schedules and triggers are listed in one place, each with an on/off switch. Jobs can run on a timer, when files change, or when a particular drive is plugged in. The editor shows the systemd timer it will install, so nothing is hidden. Timed runs use linfilecopy run <job> and their results appear in History.

10 · Icon legend

This legend is generated from tools/icons.manifest. Each ID becomes lfc-<id>-symbolic.svg in the app's GResource bundle, and GTK recolours it to match the theme. The mockup build fails if a screen uses an icon that is not in the manifest.
